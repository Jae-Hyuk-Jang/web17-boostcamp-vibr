# 문제 영역

## 관찰한 증상

- 게시글의 좋아요/댓글 반응 상태가 피드 카드, 게시글 상세 모달, 전역 스토어(`usePostReactionOverridesStore`) 여러 곳에 걸쳐 있다.
- 댓글 폴링, 낙관적 갱신, 인증 여부에 따른 분기, 전역 상태 동기화가 한 훅이나 컴포넌트 안에 섞여 있는 것으로 보인다.

## 실제 사례

- 피드에서 좋아요를 누른 뒤 상세 모달을 열면 반영이 안 되거나 반대로 어긋나는 경우가 있었던 것 같다(재현 조건은 명확히 파악 못함).
- 새 반응 기능(예: 북마크)을 추가하려면 최소 3개 파일(피드 카드, 상세 모달, 전역 스토어)을 동시에 손대야 할 것 같다는 우려가 있다.

## 초기 가설

- 서버 상태, 화면별 낙관적 상태, 전역 오버라이드 상태의 소유권과 동기화 계약이 명시적으로 정의돼 있지 않아서, 반응 관련 기능을 추가/수정할 때마다 여러 곳을 함께 고쳐야 하는 것 같다.

## 기대 효과

- 반응 상태의 단일 소유권 경계가 생기면, 새 반응 타입을 추가하거나 반응 정책을 바꿀 때 변경 범위가 좁아질 것으로 기대한다.

## 제약

- 좋아요/댓글 API 계약(`@repo/dto`)은 이번에 바꾸지 않는다.
- 로그인하지 않은 사용자의 공개 피드 열람 동작은 그대로 유지되어야 한다.
