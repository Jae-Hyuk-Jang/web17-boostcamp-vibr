# 문제 영역

## 관찰한 증상

- 좋아요 토글 시 낙관적 업데이트와 롤백 로직이 두 곳에서 각각 따로 구현되어 있다.
- `apps/web/src/components/post/PostCard.tsx`(87-88행)와 `apps/web/src/hooks/post/usePostReactions.ts`(284-285행) 양쪽에 `addLike`/`removeLike` 호출과 그 앞뒤의 낙관적 상태 처리가 중복돼 있다.

## 실제 사례

- 좋아요 실패 시 롤백 메시지 문구를 한 곳만 고치고 다른 곳은 놓친 적이 있다(정확한 커밋은 기억나지 않지만, 두 파일이 따로 관리되고 있다는 사실 자체가 반복 실수의 원인으로 보인다).

## 초기 가설

- 좋아요 토글의 낙관적 업데이트+롤백 로직이 컴포넌트와 훅에 각각 인라인으로 작성돼서, 한쪽만 수정하고 다른 쪽을 놓치는 실수가 반복되는 것 같다.

## 기대 효과

- 좋아요 토글 로직을 한 곳으로 모으면, 다음에 좋아요 관련 정책(예: 디바운스, 낙관적 업데이트 실패 메시지)을 바꿀 때 한 곳만 고치면 된다.

## 제약

- `addLike`/`removeLike` API 시그니처는 바꾸지 않는다.
- 사용자가 보는 동작(좋아요 누르면 즉시 반영, 실패 시 원래 상태로 복구)은 동일해야 한다.
