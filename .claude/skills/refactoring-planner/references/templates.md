# 문서 템플릿

각 단계에서 작성하는 문서의 최소 형식입니다. SKILL.md 본문에서 해당 단계에 도달했을 때 이 파일을 참조하세요.

## brief-original.md 최소 형식

사용자에게 아직 이 파일이 없다면 아래 형식을 채워달라고 요청하세요.

```markdown
# 문제 영역

## 관찰한 증상

- 어떤 변경이 어렵거나 반복적으로 실패하는가?
- 어느 파일·모듈·사용자 흐름에서 나타나는가?

## 실제 사례

- 최근 수정·버그·중복·성능 문제의 구체적 예

## 초기 가설

- 원인으로 의심하는 것은 무엇인가?
- 확정 사실이 아니라 가설임을 명시한다.

## 기대 효과

- 이 구조를 개선하면 어떤 다음 변경이 쉬워지는가?

## 제약

- 반드시 유지할 동작, 일정, 호환성, 운영 제약
```

## Behavior Invariants 예시 (단계 0)

```markdown
## Behavior Invariants

- 로그인하지 않은 사용자의 공개 피드 접근 결과는 바뀌지 않는다.
- 좋아요 요청 실패 시 화면과 전역 상태가 이전 값으로 복구된다.
- 큐에서 현재 곡을 제거할 때 적용되는 다음 곡 선택 규칙은 유지된다.
- 기존 DTO의 필드명과 optional/nullable 의미는 유지된다.
```

## ADR 형식 (단계 3)

```markdown
## Decision

### Context

어떤 구조 문제와 제약 때문에 결정이 필요한가?

### Decision

무엇을 선택하고 어느 범위에만 적용하는가?

### Alternatives

거부한 대안과 각각의 거부 이유는 무엇인가?

### Consequences

장점, 단점, 새로 생기는 위험과 운영 비용은 무엇인가?

### Migration

어떤 순서로 옮기며 중간 상태는 어떻게 동작하는가?

### Rollback

어떤 신호가 나오면 중단하고 어디까지 되돌리는가?
```

## 회귀 행렬 예시 (단계 4)

| 시나리오      | 기존 결과           | 검증 수준 | 실패 시 조치        |
| ------------- | ------------------- | --------- | ------------------- |
| 정상 요청     | 응답·화면 상태      | 통합      | 구현 중단           |
| 네트워크 실패 | 롤백·메시지         | 상태 전이 | 구현 중단           |
| 중복 요청     | 중복 방지/멱등 결과 | 계약      | 설계 재검토         |
| 빈 값·경계값  | 현재 예외/기본값    | 단위      | 동작 변경 이슈 분리 |

## 이슈 템플릿 (단계 5)

```markdown
# 목적

이 체크포인트가 줄이는 구조적 위험은 무엇인가?

## Scope

- 수정할 경계와 파일

## Out of Scope

- 이번 이슈에서 하지 않을 일

## Behavior Invariants

- 반드시 유지할 외부 동작

## Acceptance Criteria

- [ ] Given [기존 조건], When [동일한 행동], Then [기존과 동일한 결과]
- [ ] Given [실패/경계 조건], When [행동], Then [정의된 롤백/예외 결과]
- [ ] 새 구조의 책임과 의존 방향이 plan.md의 결정과 일치한다.

## Verification

- [ ] 실행할 테스트·lint·type check·build 명령
- [ ] 필요한 수동 또는 운영 확인

## Rollback

- 되돌릴 커밋/flag/adapter와 데이터 호환 조건

## Dependency

- 선행 이슈와 후속 이슈
```

## result.md 형식 (GATE 6)

```markdown
# Result

## 변경 요약

무엇을 어떤 경계로 옮겼는가?

## Before / After

기준선과 완료 후 지표·구조·검증 결과 비교

## Behavior Verification

보존한 동작과 테스트 증거

## Decision Review

선택한 안의 장점과 실제로 드러난 비용

## Remaining Debt

의도적으로 남긴 문제와 다시 검토할 조건

## Follow-ups

별도 feature, bug-fix, 추가 리팩터링 후보
```
