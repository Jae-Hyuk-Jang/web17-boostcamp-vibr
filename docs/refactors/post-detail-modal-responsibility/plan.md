# Plan — post-detail-modal-responsibility

## 3안

brief-fixed.md에서 라이브러리 도입 없음을 이미 확정했으므로, 워크플로우의 "③ 검증된 도구 도입안"은 자체 구현 대안으로 대체한다.

### 안 1 — 최소 개선안: 순수 계산 함수만 분리

dwell 시간 계산, 재생 시간 누적 같은 **순수 계산 로직만** 별도 유틸 함수로 뽑는다. `ref`/`useEffect`/`emitOnce` 배선은 `PostCardDetailModal.tsx`에 그대로 둔다.

### 안 2 — 경계 재설계안: 전담 훅 추출 (권장)

`usePostDetailUxLog({ enabled, postId, userId, isPlaying, currentMusicId, postMusicIds })` 훅을 신설해 5개 ref, 모달 열림 초기화 effect, 1초 tick effect, `emitPostDetailSummary`/`emitOnce`를 전부 캡슐화한다. 훅은 `{ recordPlayedMusic(musicId), emit() }`를 반환하고, `PostCardDetailModal`은 재생 콜백(`handlePlayFromPost`)에서 `recordPlayedMusic`을, 닫기/unmount 경로에서 `emit`을 호출한다.

### 안 3 — 더 넓은 재설계안: 범용 UX 로깅 시스템

이 컴포넌트뿐 아니라 앞으로 생길 수 있는 다른 화면의 체류시간 로깅까지 아우르는 범용 이벤트 로깅 유틸(analytics SDK류)을 설계한다.

## 선택: 안 2 (전담 훅 추출)

안 1은 이번 사이클의 핵심 Goal(테스트 용이성 — 컴포넌트 없이 훅만으로 검증)을 애초에 만족시키지 못해 제외한다. 안 3은 "지금 존재하지 않는 다른 화면들"을 위한 범용 설계를 미리 만드는 것이라 YAGNI 위반이고 brief-fixed.md의 Out of Scope(전면 재설계 제외)와도 충돌한다.

## ADR

### Context

`PostCardDetailModal.tsx`의 UX 로그 수집 로직(체류 시간, 재생 곡 수, 곡별 재생 시간, 중복 전송 방지)이 컴포넌트 본문에 인라인으로 구현되어 있어(ref 5개, effect 2개, callback 2개, 약 105줄), 독립적으로 테스트하거나 재사용할 수 없다.

### Decision

`apps/web/src/hooks/post/usePostDetailUxLog.ts`를 신설해 UX 로그 수집의 상태(ref)·effect·전송 로직을 전부 캡슐화한다. 훅은 재생 이벤트를 기록하는 `recordPlayedMusic(musicId)`와 요약을 전송하는 `emit()`을 반환하며, `Date.now`/`setInterval` 호출은 훅 내부에 있지만 테스트에서 대체 가능하도록 옵션으로 시간 소스를 주입받을 수 있게 한다(최소 seam).

### Alternatives

- **안 1(순수 함수만 분리)**: 기각. 배선(ref/effect)이 컴포넌트에 남아 이번 사이클의 핵심 목표(훅 단독 테스트)를 달성하지 못함.
- **안 3(범용 로깅 시스템)**: 기각. 지금 필요하지 않은 범위(다른 화면들의 로깅)까지 미리 설계하는 것은 YAGNI 위반이며 Out of Scope와 충돌.

### Consequences

- **장점**: UX 로그 로직이 `PostCardDetailModal`과 독립적으로 테스트 가능해지고, `useSwipeToDismiss`와 같은 패턴이 하나 더 생겨 컨벤션 일관성이 높아진다.
- **단점**: 이 훅은 이 컴포넌트 전용으로 설계되어(범용화하지 않음), 정말로 다른 화면에서 비슷한 로깅이 필요해지면 그때 다시 일반화 작업이 필요하다 — 의도된 트레이드오프(YAGNI).
- **새로 생기는 위험**: `emitOnce` 가드를 훅으로 옮기는 과정에서 "닫기 버튼 클릭"과 "unmount cleanup" 두 경로가 여전히 서로 안전하게 상호작용하는지 반드시 특성화 테스트로 확인해야 한다(Stage 4).

### Migration

1. `usePostDetailUxLog.ts` 작성 — 기존 ref/effect/콜백 로직을 동작 변경 없이 그대로 이관.
2. `hooks/post/index.ts` 배럴에 export 추가.
3. `PostCardDetailModal.tsx`에서 UX 로그 관련 ref/effect/callback을 제거하고 훅 호출로 교체 — `handlePlayFromPost`/`handlePlayAll`은 `recordPlayedMusic` 호출로, `handleClose`/unmount effect는 `emit()` 호출로 위임.
4. 두 단계(훅 작성 → 컴포넌트 전환)를 별도 커밋으로 나눠, 전환 전후 특성화 테스트가 동일하게 통과하는지 확인한다.

### Rollback

훅 작성과 컴포넌트 전환이 별도 커밋이라, 문제가 생기면 컴포넌트 전환 커밋만 되돌려 기존 인라인 로직으로 즉시 복구할 수 있다.
